## What's New in v0.29.1

Two fixes in the Beads view.

### Fixed

- **The Grouped view shows epics the same way the tree does, and lists each bead once.** With the Status filter's Grouped toggle on, each status group used to render the whole tree as flat rows: an epic was a plain row with a chevron and its children followed as sibling rows. Expanding an epic, or a task with subtasks, listed those children a second time, including ones that belonged in another status group, and an epic could sit in one group while its children sat in others with no header. Grouped on is now the same view as Grouped off, arranged by status. Inside each group an epic (or milestone, convoy, molecule) is the same card as in the tree, with its progress bar, count, archive button and its own child table. The card lists only that group's beads, while its count stays the epic's whole-subtree number, identical to the tree. Every bead appears exactly once, in the group of its own status, inside its epic's card or in the group's loose table. Rows no longer have a chevron or nested children; a subtask is its own row. An epic appears wherever it has beads, and in its own status group even when it has none there. A group's count is the items of that status it shows. The arrow keys follow the grouped order, visiting each card and row once.
- **The type icon no longer covers long bead ids in epic rows.** Ids longer than 14 characters were shortened to a form that was always 17 characters, longer than some of the ids it replaced and wider than the id column, so the icon was drawn over the end of the id. An id that fits is now shown in full; a longer one is shortened to what its column allows and is never longer than the id itself. The id is also clipped inside its own box, so a wider font cannot overlap the next item. The tooltip and the copy action still use the full id.
