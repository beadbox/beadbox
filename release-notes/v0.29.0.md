## What's New in v0.29.0

Two fixes for an app left open all day, a Priority filter that takes several values, keyboard fixes in the filter dropdowns, and one fix in the Backlog section.

### Fixed

- **The window no longer stays empty after macOS kills the page.** On macOS, WebKit can shut down the page's content process on its own, most often when the app has been idle for hours and the page has grown past WebKit's memory limit. The window then showed nothing but its background until you quit and reopened Beadbox. Beadbox now reloads the page the moment that happens, at most three times in ten minutes. If it keeps happening, the window shows a short message asking you to quit and reopen instead of reloading forever. The reload reconnects to the sidecar that is already running, so live updates continue.
- **The page no longer grows for as long as the app runs.** Two leaks on busy workspaces, both found while chasing the empty window above. The Chart kept a full copy of the epic tree for every change event and only let go of each copy after five minutes, so on a workspace that changes every few seconds it held hundreds of copies and reached gigabytes. It now refetches in place, and each change fetches the tree once instead of twice. The same fix covers the Trains page and the check that decides whether the Trains tab shows. Separately, the Activity feed kept every event it had ever received; it now keeps the newest 500 from live updates, and Load more still reaches everything older.
- **Backlog beads under a Backlog epic appeared twice.** A P4 bead whose parent epic is also P4 showed up under the epic's row and again in the loose Beads table below the Backlog epics, which inflated the Backlog count and let one bead be selected from two rows. Each such bead now appears once, under its epic. A P4 bead under an active epic, or with no parent, still appears in the loose table.
- **Keys pressed inside an open filter dropdown stay there.** With a dropdown open, the arrow keys moved the list's selection and Space opened a bead, so a filter row could not be toggled from the keyboard. Keys now go to the dropdown while it is open. Global shortcuts still work everywhere.
- **The workspace rail loaded the registry twice** when it mounted after a change event had already happened. It now loads once and still re-reads the registry on later changes.

### Improved

- **The Priority filter is a multi-select.** It was all priorities or exactly one. It is now a checklist from P0 - Critical to P4 - Backlog, on the same control as the Status filter. Pick several to see beads matching any of them. Selecting none, or all five, means All Priority, so the list never goes blank because of this filter. The button summarizes the selection ("2 priorities"), and a saved single value keeps its view. Keyboard: Enter opens the dropdown, the arrow keys, Home and End move through the rows, Space or Enter toggles a row, Escape closes. The Status filter gains the arrow-key movement too.
- **A memory diagnostic line in the sidecar log.** To make the next report about a growing page easy to answer, the page sends the sidecar the sizes of its main in-memory structures (query cache entries and rows, epics and beads in the tree, open details, activity events, session cache entries, listeners, the current view, subscriptions, the sidecar's own memory) once after a minute and then every five minutes, and the sidecar writes one `[memory]` line to its log. It carries counts only, never bead content. Set `BEADBOX_MEMORY_LOG=0` in the environment Beadbox starts with to turn it off.

Requires the [beads](https://github.com/gastownhall/beads) CLI, version 1.1.0 or newer.
