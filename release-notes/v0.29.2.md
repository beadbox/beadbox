## What's New in v0.29.2

A new control in the detail panel, three fixes, two of them from community reports, and a security update.

### Added

- **Add a label from the detail panel.** The metadata row could remove a label but not add one, and showed no labels area for an unlabelled bead. A "+" after the labels opens an inline input: Enter adds, Escape cancels. It suggests the labels already used in the workspace, ignores blanks, duplicates, commas and a leading dash (what bd would reject or split), and rolls back with a message if the write fails.

### Fixed

- **A bead with structured metadata no longer crashes the detail panel.** bd accepts any JSON as a bead's metadata, but the detail panel and the expanded view rendered each value straight into the page, so an object, array, number, boolean or null threw a React error and the panel went blank. Both views now share one component: string values show as before, any other value shows as wrapped JSON text, and HTML inside metadata stays plain text.
- **Custom statuses in bd 1.3's `name:category` form no longer hide your beads.** bd lets an entry in `status.custom` carry a category, such as `ticket_active:wip`, while a bead's status is always the bare name. Beadbox split the setting on commas only, so the Status filter listed "Ticket Active:Wip", no bead matched it, and a workspace whose beads were all in custom statuses showed an empty list. Statuses are now matched and shown by name everywhere: the filter, the detail panel, the advancement button (which would have written a status bd rejects) and the Activity pipeline card. Settings keeps each entry's category when you reorder or remove, and writes a new entry without one. The status list now comes from bd itself, so bd's built-in `blocked`, `deferred`, `pinned` and `hooked` are listed too.
- **Labels changed outside the app now show in the open detail panel.** bd's label writes change neither a bead's updated-at time nor its comment count, and the detail panel's freshness checks keyed on exactly those, so a label added or removed with the bd CLI, or by another client, never reached an open panel, nor a reopened one, until some other field changed. The sidecar now drops its cached bead details whenever the workspace data changes, and the panel re-reads the open bead on every refresh, served from the cache when nothing changed. This covers any write made outside the app, not only labels.
- **"All Status" means all.** With every listed status checked, a bead in a status Beadbox does not list is still shown. Unchecking a status narrows the list as before.

### Security

- **TLS library update** for the updater's downloads and outbound requests: rustls 0.23.46, fixing four published advisories. No behaviour change.
