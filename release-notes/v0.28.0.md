## What's New in v0.28.0

A Chart view: a Gantt chart for every epic.

### New

- **Chart view.** A new **Chart** tab next to Formulas (or **⌘5**) shows each epic as a timeline, with nested epics as collapsible groups and loose beads under **Ungrouped**. Each bead is a bar. Left of the dashed **now** line is what happened: from when work started to when it closed, or to now while it is still running. Right of it is the plan: a bead that has not started is placed after the beads that block it, for its estimated time (one hour when it has none), so a dependency chain reads in order and independent beads run side by side. A finished bead whose start Beadbox never saw is placed after its blockers too.
  - **hollow** — not started yet (open or deferred), drawn where it is planned;
  - **hollow red** — blocked, drawn where it is planned;
  - **solid** — being worked on (in progress, or any other active status, including your own);
  - **solid green** — closed.

  Each epic gets a summary bar spanning everything inside it. Arrows run from the end of a bead to the start of the bead it blocks, through the gaps between bars, never across them; a dependency on a bead elsewhere shows as a dot on the bar, naming the other bead. Zoom between hours, days and weeks, or fit everything on screen. Click a bead's title to open it in the Beads view. The chart uses the same filters as the Beads view and updates live.

### Changed

- **Beadbox now records when work on a bead starts.** beads keeps no start time, so the first time Beadbox sees a bead in an active status — any status other than open, deferred, blocked or closed — it stores the bead's last-updated time as `started_at` in the bead's metadata (`bd update <id> --set-metadata started_at=…`). Until now Beadbox never wrote to your beads database unless you asked it to; this is the one exception. It writes only when `started_at` is missing, never changes an existing value (a reopened bead keeps its first start), and never writes for closed beads. If the write is refused, for example on a read-only replica, Beadbox does not retry, and the chart places the bead after its blockers instead.

Requires the [beads](https://github.com/gastownhall/beads) CLI, version 1.1.0 or newer.
